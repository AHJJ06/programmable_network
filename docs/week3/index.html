What I learned

Describe your design: why these routers, LANs and links, and how you chose the addresses.

I designed a network with 4 routers (r1-r4), each connecting to one LAN containing a host (h1-h4). The routers form a ring, providing 2 possible paths between different part of the network. Each LAN uses a separate /24 subnet, such as 10.39.1.0/24 and 10.39.32.0/24. The inter-router links use separate /30 subnets, which provide 2 usable IP addresses for the 2 router interfaces. All addresses are within the 10.39.0.0 private address range.

Which route summarises several LANs? Which networks does it cover, why is it correct, and what else would it attract if you added a network inside its range?

The route 10.39.32.0/22 summarises the four /24 networks from 10.39.32.0/24 to 10.39.35.0/24. It covers the LANs for h2, h3 and h4, but not h1's 10.39.1.0/24 network. The summary is correct because these /24 networks fall within the /22 range, 10.39.32.0 to 10.39.35.255. If another network were added inside this range, traffic to it could also follow the summary route, even if no destination network actually existed there, potentially causing packets to be dropped or looped.

When you took a link down, what happened, and why couldn't your routes recover even though another path existed? What would have recovered?

When I took r1-r4 link down, traffic using that link failed. Although the ring provided another physical path through r2 and r3, the static routes did not automatically change to use it. Static routing does not discover failures and recalculate alternative paths by itself. Dynamic routing such as OSPF, could detect the failure and recalculate routes, allowing traffic to use the remaining path.

In your network, what was the control plane? Who worked out the routes, and what does that mean for a network of 40 routers?

The control plane was manual and was represented by the routing configuration in my YAML file. I worked out the routes and specified each router's destination networks and next hops. The routers then used their forwarding tables to send packets. For a network with 40 routers, manually configuring and maintaining all routes would be time-consuming and error-prone. A dynamic routing protocol such as OSPF could automatically exchange routing information, calculate suitable paths and respond to topology changes.
